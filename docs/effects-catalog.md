## 1. 动效分类总览（12 类 / 74 条）

分类法：按**运动学来源**分，不按视觉风格分——因为同一个 `energy` 驱动量在不同运动学里的映射方式不同。

| 分类 | 条数 | 共享的 `energy` 机制 | 代表条目 | 推荐主曲线 |
| --- | --- | --- | --- | --- |
| 物理仿真 | 7 | 把 `e` 翻译成力/重力/弹性，再由积分产生位置 | 双摆混沌、弹簧网格、沙漏 | 指数（力）/ 逻辑斯蒂（阻尼） |
| 波形信号 | 7 | `y=f(x,t;e)` 解析函数，改频率/谐波/占空比 | 李萨如、驻波、心电、Chirp | 线性（相位）/ 脉动（拍频） |
| 粒子场 / 群集 | 7 | 个体 + 场 + 邻域，密度来自叠加 | 流场、Boids、吸积盘、萤火虫同步 | 指数（速度）/ 逻辑斯蒂（密度饱和） |
| 几何线条 | 6 | 参数曲线/递归/网格，改拓扑参数 | 万花尺、傅里叶本轮、分形树、莫尔条纹 | 线性（角度）/ 阶跃（阶数） |
| 光与色 | 6 | 改发光半径、衰减、色相、闪烁频率 | 辉光呼吸、极光、闪电、色散 | 阈值（起辉）/ 脉动（呼吸） |
| 形变与过渡 | 6 | 形状插值、噪声位移、阈值融合 | 液态金属、metaball、故障切片 | 阈值 / 逻辑斯蒂 |
| 生命 / 角色 | 6 | 生长、苏醒、成熟度、心跳 | 藤蔓生长、蝶化、瞳孔收缩 | 阶跃（阶段）/ 脉动（心跳） |
| 数据与文字 | 6 | 数字位、指针、格数、光标 | 七段数码管、分段进度、计数器 | 线性（指针）/ 阶跃（数字位） |
| 材质与氛围 | 6 | 粒子系统 + 混合模式，密度/对比 | 雨雾、烟尘、热浪、胶片颗粒 | 指数（密度）/ 脉动（闪烁） |
| 交互反馈 | 6 | 检测 `energy` 跳变，触发一次性动画 | 档位涟漪、弹簧跟随、磁吸拖尾 | 指数（爆发衰减）/ 阈值（触发） |
| 伪 3D / 视差 | 6 | 透视除法、层速差、等距投影 | 星空跃迁、等距网格、旋转立方 | 指数（透视/速度） |
| 叙事状态机 | 5 | 离散状态 + 交叉淡化 | 三段变身、充能条、天气演变 | 阶跃（状态）/ 逻辑斯蒂（淡入） |

**「最该先做的 10 条」完整表在 [01 §14](plan/01-effects-taxonomy.md)**，筛选口径是：S 级、88–164px 可读、与现有 `particle-wave` / `kunpeng` 运动学不重复。

## 2. ⚠️ 三个已核实的现存缺陷（先修再谈新动效）

### 2.1 P0：canvas 坐标系错位，鲲鹏在面板里画不出来

| 证据 | 位置 |
| --- | --- |
| 同时挂了两个 `EffectCanvas`（一个在 `.mec-stage`、一个在 `.mec-wave`） | `lib/client.js:1389` 与 `:1398` |
| `.mec-drops` 是 `position:absolute; inset:0`，铺满各自父容器 | `lib/client.js:723` |
| 宿主算出的轨道 y = `sky + 30 + 16` = **122** | `lib/client.js:1167` |
| 但第一个 canvas 只有 `paddingTop 76 + band 30` ≈ **106**（margin 折叠后） | `lib/client.js:1388` |
| 第二个 canvas 在 `.mec-wave` 里，只有 **30** 高，而 `band.top = sky = 76` | `lib/client.js:1397` |

结论：缎带与鲲鹏被画在 `y=122`，两个 canvas 都装不下 → **实机面板里应当什么都看不到，而 `preview-effect.mjs`（284×164）是对的**。修法（按序）见 [03 §7.1](plan/03-dsh-implementation.md)：

1. 删掉 `:1398` 那个重复的 `EffectCanvas`，只留一个；
2. 让唯一的 canvas 覆盖 `sky + 30 + 58`（鲲鹏 = 164），把 `rail` 纳入同一个相对定位容器；
3. **不要**把 `trackY` 改成 `sky+30` 迁就 106 高的画布——那会把缎带画到旋钮上方。

> 状态：静态代码 + 几何推导已确认；**未做实机截图确认**（本机无浏览器截图工具）。开一次强度面板即可一眼验证。

### 2.2 `frame` 里没有 `isLight`，浅色主题会丢白

`paint` 只拿到 `energy / accent / width / height` 等，拿不到主题。凡是用白色描边、白芯渐变、`lighter` 叠加的特效，在浅色主题下会消失。两条替代路：只用 `accent` 及其 `shade()` 变体；或把亮度判断提成 `detectLightTheme()` 的结果塞进 `frame`（改宿主 1 行）。

### 2.3 计数曲线会饱和：4 档的 high 与 max 都是 14 颗

`particleCountFor(e, 4)`：`e=0.667 → 14`（`6×2^1.25≈14.3`）、`e=1 → 14`（`6×3^1.25≈23.7`，被 `min(14,…)` 截断）。5 档模型下 medium/high/max 也全是 14。**新增特效别照抄这个上限**，要么抬高 `min()` 上限，要么改用阶跃计数（每档 +1 颗可见）。

### 2.4 好消息：切换 UI 已经有了

HEAD `cf353fa` 已在面板标题加了一颗「当前特效名」的按钮，点一下循环到下一个特效，并用 `localStorage['dsh-model-effort-chips:effect']` 记住选择（`resolveEffect` 对未知 id 回退第一个，所以脏数据安全）。也就是说：**新增特效只需要注册进 `EFFECTS`，UI 侧零改动**，[03 §5](plan/03-dsh-implementation.md) 里那套「设置项设计建议」现在只剩持久化粒度（要不要按会话区分）值得讨论。


## 3. 著名 IP 目录总览（9 类 / 48 条）

原则：**只取几何语言、配色关系、构图与运动节奏**，不画可识别的角色剪影、不用 logo/剧照/音效。每条都落到「20 行 canvas 代码能画出来」的粒度。

| 分类 | 条数 | 强度语言（这类 IP 靠什么表达「更用力」） | 代表母题 | 合规格 |
| --- | --- | --- | --- | --- |
| 漫威 / DC | 6 | 能量蓄积 + 同心爆发 | 钢铁侠同心核心、雷神电弧、奇异博士曼荼罗 | 绿 |
| 日本动漫 | 7 | 呼吸法/查克拉的「流」+ 分镜式跳变 | 鬼灭呼吸法、龙珠气焰、JoJo 拟声词 | 绿～灰 |
| 国产动画与游戏 | 6 | 符号化道具 + 墨色金环 | 黑神话金箍棒、哪吒混天绫、原神七元素 | 灰（活跃商业期） |
| 西方 3A 游戏 | 4 | 世界尺度感：环境被力量接管 | 艾尔登法环黄金树、赛博朋克霓虹 | 绿～灰 |
| 科幻电影 | 5 | 尺度差 / 规则差 | 星际穿越卡冈图雅、沙丘沙暴、黑客帝国代码雨 | 绿 |
| 动画电影 | 4 | 画风本身会变（半调/水彩/剪纸） | 蜘蛛侠半调网点、你的名字彗星 | 灰（风格模仿区） |
| 神话与传统文化 | 6 | 公共领域母题，最安全 | 鲲鹏、山海经异兽、敦煌飞天、龙/凤凰 | 绿（最优） |
| 艺术与设计流派 | 5 | 规则即风格 | Y2K、蒸汽波、浮世绘、构成主义 | 绿 |
| 网络文化 / 抽象梗 | 5 | 反差与自嘲 | buff 叠满、加载骨架、像素故障 | 绿 |

完整六阶段叙事（0–5 档每档出现什么）、逐条缓动与合规章节见 [02](plan/02-ip-catalog.md)，其中 4 套可复用叙事模板是：

| 模板 | 叙事骨架 | 适配 IP | 反模式 |
| --- | --- | --- | --- |
| 形态进化型 | 小 → 大 → 长出部件 → 换形态 → 脱离母体 | 鲲鹏、鬼灭、蝶化 | 只放大不换形 |
| 能量蓄积型 | 点 → 线 → 环 → 双层环 → 爆发 | 钢铁侠、龙珠、曼荼罗 | 一直加圈，没有爆发点 |
| 环境异变型 | 静止 → 起风 → 地形变 → 天变色 → 吞屏 | 沙丘、艾尔登、赛博朋克 | 主体和环境同时动，抢焦点 |
| 角色登场型 | 无 → 剪影 → 轮廓 → 细节 → 直视 | 银翼杀手、黑碑、抽象梗 | 画到「可识别角色」= 侵权 |

## 4. 推荐落地顺序

| 批次 | 做什么 | 为什么 | 验收 |
| --- | --- | --- | --- |
| **Sprint 0（阻塞）** | 修 §2.1 的双 canvas + 坐标系；补 `frame.isLight` | 不修，新动效一律「preview 对、实机空」 | `.mec-drops` 恰好 1 个；`canvas.height/dpr === sky+30+58`；实机面板能看到缎带 |
| Sprint 1 | `pulse-ring`（4.70）、`threshold-grid`（4.40）、`field-lines`（4.30） | 综合分最高；三者分别是环/格/线，运动学互补，4 档都两两可辨 | `npm test` 四套绿；每条有 `test/effect-*.mjs` 单调性断言 |
| Sprint 2 | `starfield`（星空跃迁）、`spirograph`（万花尺）、`lissajous` | S 级纯解析，零状态，最容易一次做对 | `preview-effect.mjs` 三档出图对比 |
| Sprint 3 | IP 母题首批：鲲鹏（已存在）、钢铁侠同心核心、鬼灭呼吸法、敦煌飞天 | 公共领域/纯几何优先，商业 IP 只做抽象致敬 | 三条合规检查：无角色剪影、无 logo、无作品名 |

## 6. 一条最小可用路径（如果只想先看到效果）

```sh
# 1. 先修 P0（见 03 §7.1），否则新动效在面板里看不见
# 2. 在 lib/client.js 的 `/** Every effect the plugin knows. */` 之前插入特效对象
# 3. 注册
#    const EFFECTS = [particleWaveEffect, kunpengEffect, myEffect]
# 4. 出图（284×164，和实机同比例）
node scripts/preview-effect.mjs my-effect 0   /tmp/off.svg
node scripts/preview-effect.mjs my-effect 0.5 /tmp/high.svg
node scripts/preview-effect.mjs my-effect 1   /tmp/max.svg
# 5. 回归
npm test
# 6. 重启 DSH（手写 ESM，无构建步骤）；只换包则 ⌘⇧R 硬刷新
```
